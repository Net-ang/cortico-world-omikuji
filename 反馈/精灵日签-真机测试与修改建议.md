# `cortico-world-omikuji@0.4.2`（精灵日签）真机测试与修改建议

- **测试环境**：EndeavourOS Linux (x86_64) · Node.js `v24.22.3` · Cortico `0.2.17`
- **测试对象**：`cortico-world-omikuji@0.4.2`（作者：奶糖_net）
- **测试结论**：扩展校验（`ExtensionManager.check`）、挂载、SplitMix64 随机流、节气月相点缀、`pet`/`builtin` 双模式及媒体 `$file` 流式传输主体均能跑通；但实测复现了 **2 个逻辑/UI Bug** 和 **3 个工程优化点**，均已定位到具体文件名与行号。

## 二、问题清单与修改建议

### 🔴 1. 【核心逻辑 Bug】抽签前后「固定盐 → 每日随机盐」切换，导致同一天的签突变、且与系统前缀打架
- **位置**：`src/world.ts:99`、`src/world.ts:198`、`src/world.ts:216–230`、`src/world.ts:272–279`
- **原因**：
  - 当天尚未抽签（`omikuji-days.json` 里还没有今天的盐）时，`start()`、`envPromptVars()` 和面板 `snapshot` 调用的都是 `signFor()`（`create: false`）。此时 `#saltFor()` 会回落到**固定本机盐（`omikuji-salt.json`）**去算今天，得出了一张签（如实测中的 `第 150 签 · 大吉 · 89 分`），并写入了系统前缀 `{{omikuji.hint}}` 和开场事件 `omikuji.started`。
  - 但当用户第一次按面板「抽今天的签」或让桌宠调 `omikuji_draw()` 时，走的是 `drawFor()`（`create: true`），当场用 `crypto.randomBytes(8)` 摇了一个新盐写入 `omikuji-days.json`，导致今天的签瞬间突变成另一张（`第 239 签 · 大凶 · 0 分`）。
- **后果**：
  1. Cortico 的系统前缀**不会随工具调用自动重载**。抽签后，Bot 上下文里的系统前缀和 `omikuji.started` 事件依然写着 `第 150 签 · 大吉 · 89 分`，而工具回执和面板却是 `第 239 签 · 大凶 · 0 分`，模型看到的上下文自相矛盾。
  2. 如果用户在面板上点了抽签（摇出了新盐），再去聊天框随口聊起，Bot 脑子里的系统前缀还是旧的假签。
  3. 如果模型未调 `omikuji_draw` 直接调 `omikuji_record`（`world.ts:143` 内部调的是 `this.signFor(date)`），会把签文记在未摇盐的状态上。
- **修改建议（二选一）**：
  - **方案 A（最简，且完全契合宣传文案“种子 = 日期 + 这台机器的随机盐”）**：去掉 `daysalt.ts` 的每日现摇盐，统一只用 `omikuji-salt.json` 的固定本机盐 + 日期算签（或者在 `start()` / 当天首次 `signFor(today)` 时就调 `materializeDaySalt` 把当日盐定下来）。这样从挂载起，前缀、事件、面板、工具永远是 100% 同一张签。
  - **方案 B（保留“点抽签那一刻才真摇盐”）**：在当天未抽签（`readDaySalt(dataDir, today) === null`）时，`signFor(today)` / `envPromptVars()` / `start()` **不要回落到固定盐去算一张假签**，而是明确返回“今天尚未抽签（not drawn yet）”。

### 🔴 2. 【前端面板 Bug】扣牌状态未调 `snapshot`，导致初进页面无背景/无头像/无七天条，且与对话抽签状态脱节
- **位置**：`dist/webui.js:396–410`、`src/panel.ts:223–266`
- **原因**：
  `mount(ctx)` 末尾写的是：
  ```js
  if (ctx.memo.get('drawn', false)) await load(undefined, null, null);
  else faceDown();
  ```
- **具体表现**：
  1. **初次打开面板一片空白**：当 `ctx.memo.get('drawn')` 为 `false` 时直接走 `faceDown()`，**根本没调后端的 `snapshot`**。导致牌扣着的时候，`snapshot` 为 `null`——动态视频背景（`panel-bg.mp4`）、作者头像（`avatar.jpg`）、配置的字体（`data-font`）、顶部日期、以及底下的「这七天」横排全部不加载，必须点完「抽今天的签」才突然一起蹦出来。
  2. **对话抽签/刷新网页后面板仍扣着**：`ctx.memo` 仅存于当前前端内存。如果用户先在聊天里问了「今日气运」（桌宠已调 `omikuji_draw` 甚至已 `omikuji_record` 写好签文），或者刷新了页面，打开面板时牌依然是扣着的。
- **修改建议**：
  - 后端 `PanelSnapshot` 增加一个字段 `drawn: boolean`（`readDaySalt(deps.dataDir, deps.today) !== null || writtenOn(deps.today)`）。
  - 前端 `mount(ctx)` 时**总是先调一次 `snapshot`**，把背景、头像、字体和底下的「这七天」横排渲染出来；当 `!snapshot.drawn && snapshot.date === snapshot.today` 时，仅把中间 `stage` 渲染为 `faceDown()` 封牌即可。

### 🟡 3. 【热配置失效】`wording` 标了 `'x-hot': true`，但从 `builtin` 切到 `pet` 时不会注册 `omikuji_record`
- **位置**：`src/world.ts:130`、`src/config.ts:64`
- **原因**：`world.ts:130` 写了 `if (this.wording() !== 'pet') return [draw];`。如果启动时是 `builtin` 模式，宿主挂载 World 时只绑定了 `omikuji_draw` 一个工具；用户在面板里把模式热切换成 `pet` 后，提示词会要求模型调用 `omikuji_record`，但工具表里没有该工具。
- **修改建议**：`tools()` 始终返回 `[draw, record]`；在 `builtin` 模式下若被调用 `omikuji_record`，返回一句“当前为内置文案模式，无需记录”即可。

---

### 🟡 4. 【Token 消耗优化】`start()` 推送的 `omikuji.started` 事件建议改为 `piggyback`
- **位置**：`src/world.ts:199–206`
- **原因**：`origin: 'internal'` 的事件如果不传 `{ trigger: 'piggyback' }`，在 Cortico 的 `WakeBus` 里默认是 `trigger: 'flush'`，每次进程启动或重载 World 都会立刻唤醒主模型空跑一轮（消耗几万 token 的完整上下文）。
- **修改建议**：改为 `await host.pushEvent({ ... }, { trigger: 'piggyback' })`，让它随下一批正常消息捎带进入上下文。

---

### 🟢 5. 【性能与体积小优化】静态视频哈希缓存与背景视频瘦身
- **位置**：`src/panel.ts:76`、`src/panel.ts:167`、`src/panel.ts:192`
- **原因**：每次面板请求 `background` 或 `video` 时，都会执行 `createHash('sha256').update(readFileSync(found.path)).digest('hex')`，在主线程同步把 **16.1 MB** 的 `assets/panel-bg.mp4` 整块读进内存算 SHA-256。
- **修改建议**：
  1. 用一个模块级 `Map<string, { bytes: number; sha256: string }>` 缓存包内静态文件的大小与 SHA-256，避免每次重复同步读 16MB 文件；
  2. `assets/panel-bg.mp4`（16.1 MB）占了整个 npm 包 93% 的体积，用 `ffmpeg -crf 28` 压到 2~3 MB 左右视觉效果几乎无损，下载和加载都会快很多。
