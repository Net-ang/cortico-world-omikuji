## 1. 🔴 抽签前后签突变 —— 采纳，但用了第三种方案（不动种子）

**你说得对的部分**：确实突变，也确实会让上下文出现两套说法。你的复现很干净（150 → 239）。

**我们没有照 A 或 B 做，因为这会动到产品规则**——种子规则是作者定的：*当天第一次真抽签才摇随机盐，没抽过的日期一律按「日期 + 固定盐」算*。A 方案（去掉每日盐 / 挂载时就把今天定死）会让「点抽签才真摇」这件事消失；B 方案（没抽就报「未抽」而不给签）会让「没抽也能按固定盐读到一张」消失。这两条都是刻意要的。

**所以我们改的是「说不说」，不是「怎么算」**。根因其实是：**抽之前就把分数说出去了**，而前缀又不会随抽签刷新。修法是把分数从一切「抽之前」的地方拿掉，只让它出现在工具回执里——抽签就是定签，定签之前不报数：

1. `envPromptVars()` 只返回一段**静态**约定（不含分数、也不含措辞模式）。抽签前后一字不变，已加测试锁死。
2. 挂载事件（`omikuji.started`）：
   - 今天抽过 → `精灵日签已挂载。今天是第 150 签，大吉（89 分）。`（盐已落盘，这张不会再变，报出来是安全的）
   - 今天没抽 → `精灵日签已挂载。今天（2026-11-24）还没抽签。`（**一个字不提分数**）
3. 面板：今天没抽时中间是扣着的封牌；七天横排里今天那一格写「未抽」，不显示分数。抽过之后才显示，且那时数字已经定死。
4. 新增 `omikuji_draw({ peek: true })`：只问「今天抽了没有」，**不摇盐、不报分数**。你要的「模型能判断状态」有了，而且不会顺手把盐摇掉。
5. 你提的第三小点（`omikuji_record` 记在未摇盐状态上）也修了：`omikuji_record` 现在**先把当天的盐摇定再落盘**，签文不会记在按固定盐算的那张上。

净效果：突变在数据结构里依然存在（那是设计），但**用户与模型都看不见它**——因为抽之前没有任何地方报过分数。

## 2. 🔴 扣牌状态不调 snapshot —— 采纳，完全按你的建议

`mount(ctx)` 现在**总是先取一次 `snapshot`**：动态背景、作者头像、字体、日期、七天横排立刻到位；今天没抽过时只把中间 `stage` 渲染成封牌。`PanelSnapshot` 也按你的建议加了 `drawn`（`readDaySalt(dataDir, today) !== null`）。

顺带修掉你说的第二个现象：**对话里抽过 / 刷新页面之后面板仍扣着**——现在开屏看 `drawn`，抽过就直接给牌面，不再有「抽今天的签」按钮。

冒烟里加了 13 项断言专盯这个（开屏就有背景/头像/七天/日期、今天那格写「未抽」、抽完变成档位、已经抽过则直接给牌面）。

## 3. 🟡 热配置失效 —— 采纳

`tools()` 现在**始终返回** `[draw, record]`。内置文案模式下调用 `omikuji_record` 不再报「没有这个工具」，而是回一句：

> `2026-11-24 用的是内置文案，签文由签库给，不需要记。要让这一签由你自己写，把配置里的「措辞」切成「桌宠自己写」。`

代价是多一份工具 schema 进工具表（几十 token），换来这一类「配置改了但工具表没跟上」的 bug 不再可能。

## 4. 🟡 `omikuji.started` 改 piggyback —— 采纳

改成 `pushEvent({ ... }, { trigger: 'piggyback' })`。省下的是每次开机的那一整轮空跑。

## 5. 🟢 性能与体积 —— **前半采纳，后半驳回**

**哈希缓存：采纳。** 按 `mtime + size` 缓存大小与 sha256，文件没换就复用；面板每开一次、每重放一次动画都不再同步读 16 MB 整块文件。

**转码瘦身：驳回了，但这不是技术判断。** `assets/panel-bg.mp4` 的体积是**作者明确要求的**：不转码、就用这一段素材，16.7 MB 也认。这一条要改得作者点头，我们不能替他把素材换掉。可以考虑的折中是出两档（标准包 + 轻量包），但那要额外维护。

## 6.（来自 `功能建议.txt`）每天没抽签时提醒抽签 —— 已实现

- 挂载后每 10 分钟看一眼：今天没抽、且该天已过 9 点、且今天还没提醒过 → 推一条 `omikuji.reminder`。
- 判断的是**当下**状态：抽过就永不提醒，跨零点自动重置；提醒同样走 `piggyback`，不会自己唤醒模型。
- `peek` 工具让它能在对话里判断状态，决定是否开口。
- 提醒记账落在 `omikuji-remind.json`（同一天一次）；读不出来就当没提醒过——提醒是锦上添花，不该让挂载失败。

## 附二：作者另外要求的两条（比反馈更严）

作者看了第 1 条之后，把规矩定得更死，这两条超出了反馈的范围，但跟「突变」是同一件事：

1. **不抽就不给任何数**——不只是「界面上不显示」，而是数据结构里就没有。`PanelSnapshot.sign` 改成可空：今天没抽时是 `null`；七天横排里今天那一格 `lot`/`score`/`tierLabel` 全是 `null`；`omikuji_draw({ peek: true })` 也不报分数。所以客户端拿到的 JSON 里根本没有那天的数字，从根上不可能被谁拿去说嘴。
2. **第二天回头补录**——挂载时（以及每 10 分钟的状态巡检里）检查七天窗口内「已经过去却没有任何记录」的日子，用「日期 + 固定本机盐」把它生成出来并落盘（`source: "fallback"`），此后冻结：换配置里的盐也不再变。
   - 真抽过的（`source: "draw"`）一个字节都不改；
   - **今天永远不补**——今天没抽就是没抽；
   - 补录出来的签与 0.1.3 的口径逐字一致（日期 + 固定盐），所以「没抽的日子」和旧版算法完全对得上。

这两条合起来的效果：**抽签那一刻之前，那天的签在世界里不存在；过去的日子则一定有据可查**。

## 附一：测试口径的一处修正

你的报告让我们发现冒烟里有个**假通过**：面板固定用 `TODAY`（2026-11-23），而 World 按真实今天判断「能不能摇盐」，两边对不上，所以冒烟里点「抽签」其实从没真摇过盐。现在 `OmikujiWorld` 支持注入假时钟（`now?: () => string`，只给测试用），冒烟里点抽签会真的摇盐，签也确实会变——所以「抽前的期望值」这种写法在冒烟里也一并纠正了。
